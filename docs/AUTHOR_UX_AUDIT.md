# 作者视角 Electron UX 审查

审查时间：2026-08-12

范围：基于 v0.3 完整写作闭环的真实 Electron 截图与 A–I 操作轨迹，从长期创作多部作品的作者视角检查作品管理、写作、AI 对话、校对、历史与模型设置。未进行视觉重构，也未增加执行包以外的产品方向。

## 结论

整体流程已经适合“作品库 → 进入某部作品 → 长期分章写作 → 有选择地使用 AI → 审阅修改 → 回看历史 → 导出”的工作方式。作品级隔离始终可见；没有模型时不阻断写作；AI 不会静默写正文或把讨论自动升级为设定。

## 本轮发现并修复

| 观察 | 作者影响 | 小范围修正 |
|---|---|---|
| 项目导航换行后只剩“历史”孤立在第二行 | 左侧结构显得临时拼接，查找入口时视线跳动 | 改成稳定的 4 列两行布局，正文/灵感/故事/人物与资料/AI 数据/历史位置固定 |
| 校对抽屉与同行者同时出现时正文区域过窄 | 对照原句时可见上下文太少 | 将校对抽屉收窄到 400px，保留足够正文参照区 |
| History 原因与 Patch 状态显示英文内部值 | 作者需要翻译 `ai_edit`、`accepted`、`stale` | 映射为“AI 修改前 / 已接受 / 已失效”等作者语言 |
| 通用弹窗关闭按钮没有可访问名称 | 键盘/读屏用户难以识别，自动化定位也不稳定 | 增加“关闭”标题和 aria-label |
| 校对应用、AI 提案或候选插入失败可能只出现在控制台 | 作者不知道操作是否生效 | 在当前校对区或消息中显示可恢复错误 |
| 接受 AI 修改时，编辑器切换只读意外触发保存 | 提案立刻变 stale，作者无法接受刚生成的修改 | 禁止只读状态切换派发内容更新；Electron 复测已 accepted 并创建快照 |

## 保留现状的判断

- 最左侧继续只管理作品库、作品切换、新建、搜索与设置；项目内的正文、人物、资料、AI 数据和历史仍在第二层，不混用两种作用域。
- 正文保持宽松纸张感与较大留白，长篇写作时比卡片化布局更少干扰。
- 同行者保持右栏而非悬浮对话框；作者能同时看正文、上下文来源和历史消息。
- “理解本章”“校对”“修改提案”都是主动操作，并持续显示结果状态；没有新增一键生成整书或自动确认记忆。
- 作品库同时提供最近写作和完整列表：作品少时略有重复，但作品多时分别承担快速继续和管理筛选，暂不为小样本做结构重构。

## 未作为阻断的问题

- 在非常短的测试正文中，作品库“最近写作”和完整列表会展示同一作品；真实多作品场景下信息职责不同。
- 校对抽屉与同行者并列时正文仍会变窄，但这是短时审阅状态，且不遮挡原文；进一步改为可拖拽面板属于较大交互改造，本轮不做。
- 真实第三方 Provider 的措辞、速率限制细节与模型质量仍取决于用户自行配置的服务，本轮没有用户凭据，不作伪验收。
